# Story V-005: Wall Slide + Wall Jump

> **Status**: In Progress
> **Type**: Logic
> **Estimated**: 1.5–2h
> **Depends on**: V-002, V-003 (consumes `facing`)
> **Unlocks**: vertical level design (V-007 wall-jump shafts)

## Goal

Touching a wall while airborne and falling, with directional input pressed
*into* the wall, clamps the player's fall speed to a "slide" velocity.
Pressing jump while wall-sliding launches the player up and away from the
wall, sets `facing` to point away from the wall, and locks horizontal
input for a short window so the player can't immediately re-grab the
wall they just kicked off. No air-hover, no infinite climb on a single
wall — each wall jump must be answered by reaching the opposite wall (or
ground) before the next slide can begin.

## Acceptance Criteria

- [ ] New tunables on `Player`:
  - [ ] `@export var wall_slide_speed: float = 80.0` — clamp on `velocity.y` while sliding
  - [ ] `@export var wall_jump_velocity: Vector2 = Vector2(180.0, -240.0)` — horizontal push (away), vertical lift
  - [ ] `@export var wall_jump_lockout: float = 0.18` — seconds where horizontal input is ignored after wall jump
- [ ] New internal state:
  - [ ] `_wall_jump_lockout_timer: float = 0.0`
  - [ ] `var is_wall_sliding: bool = false` — exposed read-only for tests / future visual
- [ ] `tick_movement` signature extended with `is_wall_left: bool = false` and `is_wall_right: bool = false` (both default false, so V-002–V-004 tests still compile)
- [ ] Logic order in `tick_movement` — extends V-004's order:
  1. Decay `_wall_jump_lockout_timer`; derive `input_locked_out` flag
  2. Facing update — also gated on `not input_locked_out`
  3. Dash trigger (unchanged from V-004)
  4. Horizontal velocity — skip the assignment entirely if `input_locked_out` (lets the wall-jump push survive)
  5. Gravity (unchanged)
  6. **Wall slide check** — `pressing_into_wall` requires the corresponding `is_wall_X` and an `input_x` sign matching the wall side AND `not input_locked_out`. `can_slide` requires airborne, falling, pressing into wall. If true, clamp `velocity.y` to `wall_slide_speed`. Set `is_wall_sliding = can_slide`.
  7. Coyote / jump_buffer / dash timer decay (unchanged)
  8. Jump trigger — **wall jump takes priority**: if `jump_pressed AND can_slide`, set `velocity.y = wall_jump_velocity.y`, `velocity.x = wall_jump_velocity.x * push_dir` (where `push_dir` is the sign that points away from the wall), `facing = push_dir`, `_wall_jump_lockout_timer = wall_jump_lockout`. Else fall through to V-002 jump logic (coyote / buffer).
  9. Variable jump cutoff (unchanged) — applies uniformly to wall-jump arc as well
- [ ] `_physics_process` derives wall state from `is_on_wall()` + `get_wall_normal()`:
  - `is_wall_left = is_on_wall() and wall_normal.x > 0.5` (wall to player's left → normal points right)
  - `is_wall_right = is_on_wall() and wall_normal.x < -0.5`
  - Passes both to `tick_movement`

## Implementation Notes

- `pressing_into_wall` style (must hold direction toward wall to slide) is
  the X1/X8 default. Sticky-without-input "auto-slide" is rejected for v0.2;
  it tends to feel like the controller is fighting the player.
- The lockout timer is what makes the wall-jump arc feel committed. Without
  it, a held opposite direction would yank `velocity.x` back the moment the
  jump fired and the launch would feel toothless.
- Wall jump priority over coyote jump: if a player wall-jumps within their
  coyote window from the floor, we want the wall-jump arc, not a phantom
  ground-jump combined with a wall touch.
- We do NOT carry `_dash_timer` through wall-jump. Dashing into a wall and
  jumping should snap to wall-jump speed (180 horizontal), not preserve the
  220 dash speed. This is a deliberate departure from X8 dash-jump-out-of-
  wall behaviour and may need revisiting after playtest.
