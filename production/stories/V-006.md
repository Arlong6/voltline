# Story V-006: Charge Shot — Hold X, Release for Bigger Bullet

> **Status**: In Progress
> **Type**: Logic
> **Estimated**: 1.5h
> **Depends on**: V-003 (consumes Bullet, extends with `charge_level`)
> **Unlocks**: future weapon variants (boss-learned specials, V-?)

## Goal

Holding the `shoot` action (X key) accumulates charge. Releasing while
fully charged spawns a *charged* bullet — bigger, slightly faster, and a
distinct yellow colour. Releasing before the threshold spawns nothing
extra (the normal tap-fire on press still happens at the start of the
hold). Player visually flashes/glows while charging so the state is
readable. Resets after each fire and on release.

## Acceptance Criteria

### Player extension
- [ ] New tunables on `Player`:
  - [ ] `@export var charge_threshold: float = 0.6` (seconds of hold to fully charge)
- [ ] New internal state:
  - [ ] `_charge_timer: float = 0.0` — accumulates while shoot held
- [ ] New method `tick_charge(delta: float, shoot_held: bool, shoot_released: bool) -> bool`:
  - Adds delta to `_charge_timer` while `shoot_held`
  - On `shoot_released`: returns `true` iff `_charge_timer >= charge_threshold`, then resets `_charge_timer` to 0
  - Otherwise returns `false`
- [ ] `_physics_process` reads `shoot_released` edge alongside `shoot_pressed`, calls `tick_charge`, calls `_spawn_bullet(1)` on true return
- [ ] `_spawn_bullet` accepts `charge_level: int` param, propagates to bullet
- [ ] `_draw()` swaps body colour while charging:
  - `_charge_timer >= charge_threshold` → body renders in `_COLOR_CHARGE_READY` (yellow)
  - `0 < _charge_timer < threshold` → body lerps body↔white via sin pulse for "charging" feedback
  - else → standard body colour

### Bullet extension
- [ ] `@export var charge_level: int = 0` (0 = normal, 1 = charged)
- [ ] Tick speed = `SPEED_CHARGED` if level ≥ 1 else `SPEED_NORMAL`
- [ ] Draw size + colour vary by level

## Implementation Notes

- Tap-fire and charge-fire are independent: pressing X always fires a
  normal shot on the rising edge (V-003 `tick_shoot` unchanged); the
  charge fires *additionally* on release if held long enough. Standard
  X-buster behaviour — one button cycle can produce normal-then-charged.
- Charged shots fire **regardless of `_shoot_cooldown`**. The hold
  itself is the gating mechanic; you can't accidentally rapid-fire
  charges.
- `_charge_timer` resets on release whether or not it fired, so a half-
  charged release doesn't preserve "leftover" charge for the next press.
